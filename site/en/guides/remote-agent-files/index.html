QTERM / GUIDE

Paste images and files to a remote CLI agent

Paste local context into a remote terminal, wait for the upload, then give the server path to your CLI agent.

1. Use a connected SSH terminal

This guide covers the Qterm desktop SSH terminal. Connect to the server and confirm normal command input first. The server must permit SFTP and writes to the staging directory. Your agent needs permission to read the resulting path.

Pasting a file into a local terminal produces a local path. A path on your computer is not a file on another server.

2. Copy and paste a screenshot

Copy an image with your operating system’s screenshot tool. Focus the remote Terminal Block and paste. Wait for the upload to finish, inspect the inserted server path or the agent’s image representation, then add your request and send it.

3. Copy files or folders

Copy a file or folder object in Finder, Explorer or your Linux file manager, then paste into the remote terminal. Copy the file itself, not its filename as text. Once uploaded, Qterm inserts its absolute remote path without executing a command.

To put files in a specific project directory, open that directory in a Files Block and use upload or drag and drop. Terminal staging and uploading to a chosen directory serve different purposes.

4. Verify before sending

Check that the upload finished and the path is correct, then tell the agent what to do with it. A path only identifies a file: image recognition, supported formats and reading permissions depend on the CLI and model.

You can cancel an active upload. Diagnose a failed transfer before using its result. Manage uploaded material according to your server’s data-retention practices.

Troubleshooting

  • Only text is pasted: text takes precedence when present in the clipboard. Copy the image or file object again.
  • Upload rejected: check SFTP access, free space, staging-directory permissions and the SSH connection.
  • Agent cannot find the file: confirm that the agent and terminal can access the same filesystem. An agent inside a container may not see a host path.
  • Image is uploaded but unreadable: verify image input support in the CLI and model.
  • Need a permanent destination: upload through the Files panel after choosing the target directory.
