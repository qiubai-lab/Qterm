QTERM / GUIDE

Run Claude Code or Codex over SSH

Keep your agent and repository on a development server. Use Qterm to bring its terminal, files and Git review into one workspace.

1. Prepare the remote environment

You need an SSH-accessible development server, login credentials and a project repository. Install and authenticate your chosen CLI on that server using its official instructions. Its account, model access and network requirements are separate from Qterm. Qterm does not include a model, credits or an agent installer.

Verify that ordinary SSH access, repository permissions and the CLI work before diagnosing the workspace.

2. Connect a terminal to the server

Install Qterm and save the host, port, username and authentication method in connection management. Return to a Terminal Block and select the connection from its top-left target selector. On first connection, compare the host-key fingerprint with a trusted value from your server administrator before accepting it.

Saving a profile alone does not connect. Unlock the credential vault when requested. Investigate changed host keys before trusting a replacement.

3. Start the agent inside the project

Change to your actual remote repository before starting the installed CLI. This example uses Codex; use claude on the last line for Claude Code. All commands run on the remote server.

cd /path/to/your/project
git status
codex

Replace the example path. Give the agent a concrete task and constraints. Approval and execution permissions remain controlled by the agent itself; pasting a prompt into Qterm does not automatically execute it.

4. Send local context to the remote agent

Copy an image, file or folder on your computer, then paste into the connected remote terminal. Qterm stages it on the server through the SSH session and inserts its remote path when the upload completes. Review the input before sending it.

Read the image and file paste guide for permissions, clipboard precedence and image-support limitations.

5. Inspect files and review the diff

Open Files or Git from the terminal. When OSC 7 is enabled and the shell reports its directory, Qterm opens at that path. Otherwise, use the directory picker to choose the repository.

Inspect generated files, review each diff, stage only the intended changes and write a commit message. Run project tests in the terminal. Commit, Pull and Push are separate actions; inspect the branch before synchronizing.

Troubleshooting and session limits

  • Command not found: check the CLI installation and PATH on the server.
  • Wrong directory: check the OSC 7 setting and shell support, or choose the directory manually. The temporary shell hook may appear in command history.
  • Long tasks: switching workspaces preserves active sessions, but this does not promise process recovery after a lost connection, application exit or restart. Configure server-side session management if needed.
  • Notifications: the tool must actively emit a supported OSC message for Qterm to display it.
