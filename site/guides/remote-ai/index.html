QTERM / 使用指南

通过 SSH 使用 Claude Code 与 Codex

让 Agent 在服务器上的项目里工作，用 Qterm 在同一工作区完成终端交互、文件检查和 Git 审阅。

1. 准备远程开发环境

准备一台可通过 SSH 登录的开发服务器、登录凭证和已存在的 Git 项目。在服务器上按所选 Agent 的官方说明安装 CLI 并完成登录；相关账户、模型权限和网络访问由你单独配置。Qterm 不提供模型、不附赠额度，也不会替你安装 Agent。

先确认普通 SSH 登录、项目读写权限和 CLI 本身可用，再排查工作台层面的问题。

2. 在终端中连接服务器

安装 Qterm 后，在连接管理中保存主机、端口、用户名和认证方式。回到 Terminal Block，使用左上角目标选择器选择该连接。首次连接时，将显示的主机密钥指纹与服务器管理员提供的信息核对，再确认信任。

保存连接配置不会立即发起连接；凭证库若已锁定，需要先解锁。主机密钥变化时，应先查明服务器变更原因。

3. 进入项目，再启动 CLI Agent

在远程终端中切换到真实项目目录，然后启动你已经安装的 CLI。下面以 Codex 为例；使用 Claude Code 时将最后一行替换为 claude。这些命令在远程服务器上执行。

cd /path/to/your/project
git status
codex

将示例路径换成实际目录。告诉 Agent 具体目标和约束；Agent 自身的审批与执行权限仍由该工具管理。Qterm 不会因粘贴提示词而自动执行它。

4. 把截图和文件交给远程 Agent

在本机复制截图、文件或文件夹，然后在已连接的远程终端粘贴。Qterm 将内容通过当前 SSH 会话暂存到服务器，完成后插入远端路径。检查上传结果和输入区，再决定是否发送给 Agent。

查看截图与文件粘贴教程，了解文本优先、权限不足和图片读取能力的边界。

5. 并排检查文件与 Git 变更

从终端打开 Files 或 Git Block。启用 OSC 7 且 Shell 正常报告目录时，Qterm 可从当前路径打开；未报告路径时，使用目录选择器定位仓库。

先在 Files 中检查生成结果，再在 Git 中逐文件查看差异、选择性暂存并填写提交说明。测试仍需要在终端中运行。提交、Pull 和 Push 是独立操作，先检查目标分支再执行。

常见问题与会话边界

  • 找不到命令：检查 CLI 是否安装在远程服务器，以及远程 Shell 的 PATH。
  • 文件面板没有跟随目录：检查高级设置中的 OSC 7 和 Shell 支持；也可手动选择目录。临时 Shell Hook 可能进入命令历史，详见 README。
  • 长任务：工作区切换保留当前运行中的会话，但不承诺断网、关闭应用或重启后恢复进程；需要断线续跑时自行配置服务端会话管理。
  • 通知：只有工具主动发出支持的 OSC 消息时，Qterm 才能呈现相应提醒。
