QTERM / 使用指南

用 Docker 自托管 Qterm Web 工作台

需要从浏览器进入自己的开发环境时，可以部署 Qterm Web 运行时。它是真实的单用户服务，与官网的模拟 Demo 不同。

1. 确认部署前提

准备 AMD64 Linux 主机、本机 Docker Engine，以及支持 up --wait-timeout 的 Docker Compose v2。当前发布镜像为 linux/amd64；ARM 主机需要模拟执行支持，并非原生 ARM 镜像。

默认容器以 root 运行并使用 host 网络，登录用户可访问该容器开发环境。HTTP 仅适用于受信任内网或 VPN；公网应配置 HTTPS 反向代理。

2. 安装到新目录

在计划保存部署数据的父目录执行。脚本会新建 qterm/，生成访问密码并启动服务，不覆盖已有目录。

# 在当前目录下新建 qterm/ 并部署 Web 服务
curl -fsSL https://raw.githubusercontent.com/qiubai-lab/Qterm/main/scripts/install-server.sh | sh

脚本默认使用端口 2654，检测主机 IPv4 地址，健康检查成功后输出访问地址和登录密码。部署文件、数据和密码文件分别保存在生成目录中；妥善保管密码，不要提交到版本库。

3. 使用正确的访问地址

使用安装输出的地址登录。浏览器地址的协议、主机和端口必须与 QTERM_PUBLIC_ORIGIN 完全一致。公网、NAT 或多网卡环境应显式指定地址；把环境变量传给管道右侧的 sh：

# 指定浏览器访问地址，请将下方 IP 替换为实际内网地址
curl -fsSL https://raw.githubusercontent.com/qiubai-lab/Qterm/main/scripts/install-server.sh | \
  QTERM_PUBLIC_ORIGIN=http://192.168.1.10:2654 sh

将示例 IP 替换成真实内网地址。设置 HTTPS origin 不会自动配置代理或证书。Web 登录密码与凭证库主密码互相独立；首次进入后按界面设置凭证库。

完整部署文档提供内网直连、Nginx HTTPS、端口配置和手动部署步骤。

4. 升级、日志与备份

在生成的部署目录中执行：

# 进入安装脚本生成的部署目录
cd qterm
# 查看最近 100 行服务日志
docker compose logs --tail 100 qterm
# 拉取新版容器镜像
docker compose pull
# 后台启动服务，最多等待 90 秒通过健康检查
docker compose up -d --wait --wait-timeout 90

升级前按照完整部署文档备份数据与配置，必要时保留原镜像标签或 digest 供回滚。服务启动失败时在现有目录排查日志，不要重新运行安装脚本覆盖部署。容器可写层中的自行安装工具可能在重建后丢失，应将环境构建与持久化纳入自己的部署方案。

桌面版、Web 服务与 Demo

桌面版连接本机及远程环境；自托管 Web 服务在你的容器中执行实际操作；官网 Demo 只有虚构会话。HTTP 环境下浏览器主动剪贴板 API 可能受限，可使用键盘复制粘贴、文件选择或拖放。
