通过 SSH 审阅远程 Git 差异并提交

Agent 在服务器上修改代码后，直接打开同一远程仓库，检查它改了什么，再决定提交哪些内容。

1. 打开正确的远程仓库

连接 SSH 终端，切换到项目目录。通过终端打开 Git Block；OSC 7 正常上报目录时会使用当前路径，也可通过目录选择器定位本机或已连接服务器的仓库。

先检查面板的连接目标、仓库目录和分支。项目需要已经是 Git 仓库，服务器上需要可用的 Git；工作区中的不同面板可以拥有独立目标。

2. 区分工作区与暂存区

工作区包含未暂存修改，暂存区是下一次提交的候选内容。选择文件查看对应差异，并排比较增删内容。先检查 Agent 是否改了无关文件或生成了不应提交的产物。

3. 测试、选择性暂存与提交

在远程终端执行项目要求的测试。回到 Git 面板逐文件或多选暂存需要提交的改动；错误加入的文件可以取消暂存。填写能说明改动目的的提交信息，检查已暂存列表，再提交。

提交前需在远程环境配置好 Git 作者身份。不要将“丢弃更改”当作取消暂存：丢弃会影响文件内容，应仔细阅读确认提示。

4. 单独处理同步与冲突

本地提交不会自动推送。检查目标分支、上游关系与远端访问凭据，再执行 Pull、Push 或发布分支。Qterm 的主操作建议根据当前状态变化，不会把提交和推送自动串联起来。

遇到合并冲突时，在冲突工作台比较 Current 与 Incoming，编辑结果、保存并继续合并；决定放弃本次合并时使用中止操作。运行测试后再同步。

演示与真实仓库的区别

在线 Demo 可以体验虚构仓库的差异、暂存与提交，不执行真实 Git 操作；分支、同步、历史和冲突等能力并未完整模拟。请使用桌面端操作实际仓库。
