# Product Spec

## Product Goal

构建一个体积小、资源占用可控的 Windows/macOS/Linux 桌面终端工具，为用户提供安全的 SSH 交互和文件传输体验。

## Core Users

- 需要管理远程 Linux/Unix 主机的开发者和运维人员。
- 使用密码、可迁移私钥凭证或 SSH Agent 连接远程主机，并希望跨设备复用关键连接信息的用户。

## Core Flows

1. 用户维护主机、端口和用户名等非敏感连接配置。
2. 用户在独立凭证管理中添加密码或导入私钥，连接只引用可复用凭证；私钥凭证可按需生成并复制 OpenSSH 公钥，以便配置服务器；也可使用一次性密码或 SSH Agent。
3. 用户确认未知主机密钥，应用阻断已知主机密钥变化。
4. 应用每次启动时保持凭证库锁定；用户解锁后，Rust 后端按连接引用解析密码或私钥并进入交互终端。初始化时先由应用内确认说明恢复密钥用途，用户明确点击保存后再选择本地位置；恢复文件默认命名为 `qterm-recovery-{Unix 时间戳}.key`。忘记主密码后先加载恢复文件，由 Rust 完成有效性校验；验证成功后才允许输入新主密码，随后返回应用显示新密钥保存确认，用户再次点击后才打开保存窗口并轮换恢复文件。用户只可在凭证管理中明确显示单条密码；手动锁定或凭证库有效期届满会清除运行时密钥。
5. 用户通过同一产品上传或下载远程文件。
6. 用户通过顶部 Workspace 标签区分长期工作环境，不需要下拉框或内部终端 Tab。
7. 用户在单个 Workspace 中分割多个 Terminal Block，并在切换 Workspace 后继续保留活动会话和终端输出。
8. 用户可从终端当前目录或右侧工具轨打开 Files Block，并在文件窗口内独立选择本机或不同远程 SFTP 连接。
9. 用户选择已配置远程目标时，应用优先按 profile 认证偏好直接连接；“手动”偏好或保存凭据不可用/连接失败时，认证弹窗提供一次性密码、已有凭证或 SSH Agent。临时选择不回写 profile。远程 Files Block 继承目标后自动建立独立 SFTP 会话。
10. 用户可用一层连接分组整理 profile，在分组内新建或把连接移到其他分组；删除分组只移除组织结构，连接安全回到“未分组”。
11. 用户可在系统设置的通用分类中修改连接、凭证与网络转发规则的可迁移目录；默认使用 `~/.qterm`，新目录在保存时初始化，`connections.json`、`secrets.vault` 与 `network-forwards.json` 由用户手动迁移并在重启后生效。
12. 用户可从右侧工具轨选择只锁定凭证库，或同时锁定当前应用的终端界面与凭证库；也可配置在 Qterm 内无键盘、指针或滚轮操作达到指定时长后自动执行后者。终端锁只能通过主密码同时解锁终端和凭证，且不会跨应用重启保留。
13. 用户可从右侧工具轨或远程 Terminal Block 创建 Network Block，按连接 profile 管理本地端口转发、远程端口转发和本地 SOCKS5 动态代理；配置可跨 Network Block 复用，但每个 Block 独立连接和运行，应用恢复后默认停止。
14. 用户只从 Terminal、Files 或 Network Block 左上角的目标选择器选择连接；连接管理只维护 profile 与分组，浏览、编辑、保存或复制配置不会改变任何 Block 的当前目标或发起连接。
15. 用户从连接管理页头常驻的“导入”入口先看到 SSH Config 选择说明，明确点击“选择配置”后才调用默认定位 `~/.ssh` 的系统选择器。文件选定后在独立 Tab 中确认连接与凭证，所有连接统一进入“未分组”并由用户导入后自行调配；`IdentityFile` 默认不导入，只有用户逐项勾选并解锁凭证库后才纳入凭证管理。相同公钥复用已有凭证，同名不同公钥仍可导入。复杂的 Match、代理和不支持配置只产生提示，不改变现有 SSH 运行时行为。

## Product Principles

- 密码和私钥只有在用户明确添加到凭证库时才持久化；主密码派生密钥与独立高熵恢复密钥分别包装同一个随机数据密钥，凭证使用 AES-256-GCM 逐条加密。凭证名称、类型和算法作为非敏感摘要可在锁定状态用于显示连接引用，但更改引用或使用秘密前必须解锁。恢复文件由用户自行离线保管，主密码、恢复密钥、私钥正文和 data key 不传给前端、不记录日志。
- 对未知主机要求明确确认，对密钥变化默认失败关闭。
- 优先使用内置、可控的纯 Rust SSH 实现，降低外部运行时依赖。
- 私钥由用户通过系统选择器，或在 SSH Config 导入预览中逐项明确授权导入；文件正文只在 Rust 边界读取并加密，连接配置不保存设备路径。
- SSH/SFTP 单会话垂直切片完成后，产品演进为 `Workspace → Terminal Block layout` 的多会话工作台；顶部每个标签就是 Workspace，终端画布始终是视觉主体，连接与设置按需出现。
- 文件窗口是一等布局 Block，连接生命周期不依赖终端；终端中的文件夹按钮只传递目标与当前路径作为打开快捷方式。
- 连接分组只承担组织作用，不改变 profile 身份、凭据归属或 Terminal/Files 会话引用；“未分组”是派生视图而不是可删除实体。
- 连接管理器的选中项只表示当前编辑对象，不代表任何 Workspace Block 的连接目标；Block 左上角目标选择器是目标切换和连接发起的唯一入口。
- 右侧工具轨提供独立凭证管理；整体清除必须要求用户准确输入 `确认清除`，并同时删除保险库、运行时密钥和全部凭证引用，不删除连接与 Workspace。
- 系统设置提供两项跨平台设备安全策略：凭证库有效期默认 3600 秒，从最近成功解锁或修改主密码开始且普通操作不续期；终端空闲锁默认关闭，启用后只由 Qterm 内的键盘、指针按下和滚轮操作续期。安全设置不随可迁移目录迁移。
- 终端锁是当前应用进程内的隐私与误操作防护：到期时先锁定凭证库，遮罩只阻断顶部标题栏下方的终端工作区，不暂停或终止 SSH/SFTP/Network/local PTY；顶部 Workspace 切换与窗口控制保持可用。锁定状态和最近活动时间不持久化，也不替代操作系统会话锁。
- 默认可迁移目录为 `~/.qterm`，只包含 `connections.json`、`secrets.vault` 与 `network-forwards.json`。用户可选择其他绝对目录；应用只初始化目标目录，不自动迁移、覆盖或删除旧文件，路径变更在重启后生效。known-hosts、Workspace 与安全设置保持系统 app-data 路径，不受该配置影响；固定系统 app-config 只保留用于启动定位的可迁移目录指针。
- Web 和 AI Agent 属于潜在后续方向，不作为当前架构和交付范围的前提。
- 网络转发规则按连接 profile 全局共享并保存到独立的可迁移配置；Network Block 只选择 profile 并持有当前进程内运行状态。Local/SOCKS5 与 Remote listener 默认只绑定 loopback，非 loopback 必须明确暴露风险，且规则不会随应用启动或 Workspace 恢复自动运行。
- 用户确认删除连接时同步删除所有引用该 profile 的网络转发规则并关闭相关 Network session；共享凭证只解除引用、不随连接删除。确认界面必须明确说明不可撤销的级联范围。
