## Goal

让用户在编辑本地转发、远程转发或 SOCKS5 规则时，能直接看懂流量从哪里进入、在哪台设备监听、最终到达哪里，并能将示意中的设备角色与表单字段对应起来。

## Scope

- 用动态数据流示意条替换规则编辑器顶部的静态类型说明卡。
- 远程转发展示“访问端 → 服务器监听地址 → 本机目标地址”。
- 本地转发展示“访问端 → 本机监听地址 → 服务器侧目标地址”。
- SOCKS5 展示“应用 → 本机 SOCKS5 监听地址 → 服务器网络”。
- 示意条实时展示当前地址和端口值；空值显示明确占位。
- 在监听地址和目标地址标签前显示与当前规则类型一致的设备图标。
- 使用连续细线连接三段数据流，并以从左向右移动的数据脉冲表达方向。

## Constraints

- 复用 Qterm 现有暗色紧凑弹窗、颜色令牌和图标风格。
- 不改变网络规则的数据结构、保存行为、校验规则或 Tauri 接口。
- 保持表单标签、键盘操作和辅助技术可访问性。

## Non-Goals

- 不实现可交互拓扑编辑器。
- 不改变网络规则类型选择页或网络规则执行语义。
- 不新增 UI 或动画依赖。

## Acceptance

- 远程转发的示意顺序和字段图标明确对应服务器监听、本机目标。
- 本地转发的示意顺序和字段图标明确对应本机监听、服务器侧目标。
- SOCKS5 不显示目标地址字段，并能解释从本机代理到服务器网络的流向。
- 修改地址或端口后，示意条中的端点值同步更新。
- 窄弹窗下内容不溢出，空值、禁用状态和既有校验提示仍可理解。
- 节点之间不显示箭头字符；连接线方向动效克制，并在减少动效设置下提供静态方向提示。
- 连接线与左右节点保持一致的紧凑间距；节点按内容占宽并限制最大宽度，剩余空间由连线平均吸收。

## Acceptance To Verification

- 通过 NetworkRuleDialog 组件测试覆盖三种模式的流向、设备图标和实时值。
- 通过既有保存与校验测试确认行为未改变。
- 通过 appStyles 样式契约和 `pnpm check` 验证布局、类型与构建。

## Open Questions

无阻塞问题。

## Recommended Approach

采用规则类型驱动的三节点只读数据流组件，并直接从表单 state 派生端点文案。节点间使用基础细线与单个短脉冲，比分段箭头更连贯，也比整线扫光更像离散数据包且更克制；减少动效时将脉冲固定在目标端。
