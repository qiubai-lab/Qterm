## Goal

用符合终端操作习惯和 Qterm 视觉语言的自定义右键菜单替代 WebView 原生菜单，让用户能安全、快速地完成选区复制、剪贴板粘贴和缓冲区操作。

## Scope

- 仅评估终端内容区域的上下文菜单，不覆盖终端块标题栏、文件窗口或网络窗口。
- 第一阶段菜单按以下顺序分组：
  - `复制`：仅在终端存在非空选区时启用。
  - `粘贴`：仅在终端可输入时启用；通过 xterm 的 `paste` API 写入，保留 bracketed paste 行为。
  - 分隔线。
  - `全选`：选择当前主缓冲区或备用缓冲区中的全部可选内容。
  - 分隔线。
  - `清除终端缓冲区`：复用标题栏现有动作和语义。
- 剪贴板来源不区分终端内部或外部；菜单与快捷键统一读写系统纯文本剪贴板，并粘贴到当前触发终端。
- 快捷键按平台兼容：
  - macOS 使用系统习惯的 `⌘C / ⌘V`。
  - Windows 同时支持 `Ctrl+Shift+C / Ctrl+Shift+V` 与桌面习惯；`Ctrl+C` 仅在存在选区时复制，否则必须继续向终端发送中断字符，`Ctrl+V` 默认粘贴。
  - Linux 默认保留终端习惯的 `Ctrl+Shift+C / Ctrl+Shift+V`，不无条件截获 `Ctrl+C / Ctrl+V`。
- 若后续需要跨平台统一 `Ctrl+V`，应提供可配置的“桌面剪贴板快捷键”模式，而不是硬编码覆盖终端程序对 `Ctrl+V` 的使用。
- 多行粘贴或超长粘贴在真正写入会话前显示紧凑确认，明确行数/字符数并允许取消；确认内容不得回显敏感全文。
- 支持鼠标右键、键盘菜单键与 `Shift+F10`，并实现菜单内方向键、Home/End、Enter/Space、Escape 操作。
- 菜单按实测尺寸在视口内翻转/夹紧；打开后保持终端选区，关闭后把焦点还给终端。
- 第二阶段可独立评估：终端内容搜索、滚动到顶部/底部、链接上下文动作、复制当前工作目录。

## Constraints

- 复用 `@xterm/xterm` 的 `hasSelection`、`getSelection`、`selectAll`、`paste` 和 `clear` 能力，不直接操作 xterm 内部 DOM 或隐藏 textarea。
- 复制与粘贴使用已接入的 Tauri 剪贴板插件；当前能力配置只有 `allow-write-text`，实现粘贴时需最小化新增 `allow-read-text` 权限，不开放图片或 HTML 剪贴板权限。
- 菜单保持 Qterm 紧凑暗色工作台风格，使用现有色彩 token、图标和菜单交互模式，不引入新的 UI 库。
- 终端锁定、会话未连接或正在认证时，输入型操作必须禁用；只读的复制、全选和缓冲区导航仍可按实际状态使用。
- 菜单不得因靠近分屏边缘而被终端块裁切。
- 清除缓冲区沿用现有非破坏性语义：清除前端回滚缓冲，不向 Shell 发送 `clear` 命令，不重置会话。

## Non-Goals

- 不提供 `剪切`：终端输出不是可编辑文本，剪切语义不成立。
- 不提供拼写与语法、替换、文本转换、检查元素等 WebView 内容编辑功能。
- 第一阶段不加入断开/重连、关闭终端、切换连接、上下/左右分屏、打开文件或网络窗口；这些已有常驻标题栏入口，放入内容菜单会增加噪音并混合内容操作与布局管理。
- 第一阶段不提供“复制命令”“复制命令输出”“复制当前行”；这些需要可靠的 Shell integration/语义标记，不能仅凭视觉行推断。
- 不将“点击右键即复制选区”设为默认行为，避免误覆盖剪贴板并保持菜单可发现性。

## Acceptance

- 在终端内容区右键只出现 Qterm 菜单，不出现 WebView 原生菜单。
- 没有选区时 `复制`明确禁用；存在跨行或宽字符选区时复制文本准确且选区不因菜单打开而丢失。
- `粘贴`通过 xterm API进入会话；多行或超长文本必须先确认，取消后不产生任何终端输入。
- Tauri capability 只新增读取纯文本所需权限，不扩大到图片、HTML 或通用剪贴板访问。
- `全选`、`清除终端缓冲区`与现有 xterm/Workspace 行为一致。
- 锁定、未连接、连接中、已连接、主缓冲区和备用缓冲区状态均有明确行为。
- 菜单可由键盘完整操作，Escape/外部点击关闭，关闭后焦点恢复到触发终端。
- 从浏览器、编辑器、文件窗口或另一个终端复制的纯文本均可通过相同菜单动作和平台快捷键粘贴；来源不产生行为差异。
- `Ctrl+C` 在无选区时仍能中断前台进程；未启用桌面剪贴板模式的平台上，`Ctrl+V` 仍可被 Shell、vim/tmux 等终端程序接收。
- 在分屏、窗口四角、最小支持尺寸和高 DPI 缩放下，菜单完整可见且不被裁切。
- 菜单样式与现有文件/网络菜单一致，并支持 reduced motion、reduced transparency 和 focus-visible。

## Acceptance To Verification

- `TerminalPanel` 组件测试覆盖鼠标/键盘打开、原生菜单阻止、复制启用状态、选区保持、粘贴与多行确认、全选、清除、关闭和焦点恢复。
- Workspace 集成测试覆盖会话状态与终端锁定时的禁用规则，以及多终端分屏时动作只作用于触发菜单的终端。
- 定位测试覆盖右下角翻转、四边夹紧、菜单动态高度和窗口 resize/scroll 后关闭。
- 手工验证 macOS、Windows/Linux 快捷键标签与行为，并检查 IME、备用屏幕程序（如 vim/tmux）和 bracketed paste。
- 实现后运行相关 Vitest，再运行 `pnpm check`。

## Open Questions

- 多行粘贴确认阈值建议定义为“包含换行或超过 1000 个字符”；实现前可根据产品对安全性与效率的取舍微调，但不影响菜单第一阶段范围。

## Recommended Approach

推荐“聚焦型菜单”：第一阶段只交付复制、粘贴、全选、清除缓冲区四项，并加入多行粘贴保护。它覆盖最高频终端任务，能彻底去掉截图中无关的 WebView 编辑项，同时避免把标题栏已有的分屏、关闭、文件和网络动作重复塞进菜单。

备选一是“极简菜单”，只保留复制和粘贴，开发成本最低，但没有解决长回滚内容的全选和缓冲区管理，产品感偏弱。备选二是“全功能菜单”，同时加入搜索、链接、目录、滚动、分屏和会话管理；发现性更强，但菜单会过长，且搜索、链接和命令语义需要额外能力，建议拆到第二阶段按使用反馈增加。
