## Goal

让添加私钥凭证页面先准备并预览候选私钥，待名称与密钥均通过校验后由用户明确保存，避免选择或生成动作直接写入凭证库。

## Scope

- 在“添加私钥凭证”编辑区固定显示凭证名称和可选私钥口令。
- 将表单下方剩余高度等分为文件导入区与生成私钥按钮。
- 文件导入区支持点击打开系统文件选择器，以及拖放单个本地私钥文件。
- 生成入口沿用现有算法和注释配置流程，并复用已填写的凭证名称。
- 名称始终为空且为必填项，不再根据文件或算法自动命名。
- 选择文件或生成密钥只创建 Rust 内存草稿，不写入凭证库。
- 已选择的操作面显示文件名或生成算法、使用高亮选中态，并禁用另一个操作面。
- 右下角固定显示取消与保存按钮；只有名称和候选密钥均存在时才能保存。
- 两个操作面的图标与文案作为整体居中，生成入口不显示尾部箭头。

## Constraints

- 私钥正文不得进入 React 状态或 IPC；拖放只传递本地路径，由 Rust 后端限量读取、解析并加密保存。
- 保留现有凭证管理器布局、反馈、键盘焦点和忙碌态语义。
- 只处理单个拖放文件；多文件拖放不得静默选择其中一个。
- 下方两块在可用高度内严格 1:1 分配，并允许紧凑窗口下由编辑区滚动兜底。

## Non-Goals

- 不修改凭证数据模型、密钥格式支持、生成算法或存储格式。
- 不重做凭证列表、详情页或密码凭证创建页。
- 不允许浏览器读取私钥正文。

## Acceptance

- 名称与私钥口令在添加私钥页面始终可见。
- 文件区具有虚线边框，点击可选择文件，拖入单个文件时有明确状态并可完成导入。
- 名称为空时仍可选择、拖放或生成候选密钥，但不会自动填入名称。
- 选择或生成后凭证列表不变化；只有点击保存才新增凭证。
- 缺少名称或候选密钥时保存不可用，提交处理仍执行同等后端校验。
- 文件区与生成按钮各占表单下方剩余高度的一半。
- 生成私钥入口仍可配置算法和注释；名称为空时随算法生成 `ed25519_<随机字符>` 或 `ecdsa_p256_<随机字符>`，手动名称保持不变。
- 两个操作面的内容居中，生成入口没有尾部箭头。

## Acceptance To Verification

- Testing Library 覆盖固定表单、空名称点击导入、文件名回填、单文件拖放、多文件拒绝、自动生成名称和生成入口。
- IPC 单元测试确认选择器导入不传路径、拖放导入仅传路径而不传私钥正文。
- Rust 测试与类型检查覆盖新增窄命令和既有文件读取限制。
- CSS 契约测试确认剩余空间、1:1 行分配、虚线边框和滚动所有权。

## Open Questions

无阻塞问题；按单文件拖放实现。

## Recommended Approach

保留现有 `CredentialDialog` 状态机，将本地导入表单内联到 private-key create stage；用 Tauri 原生拖放事件接收路径，并新增单用途 Rust 命令复用现有安全读取与导入逻辑。相比新建向导，此方案状态更少、视觉更直接，也不复制私钥校验规则。
