# 静默重试远程 Shell 探测并移除手动集成

## Goal

让远程目录自动集成在短暂探测故障下自愈，同时保证无法识别 Shell 时不会阻塞或打扰正常终端连接，并移除用户手动复制 OSC 7 Hook 的产品路径。

## Scope

- 区分成功、明确不支持和瞬态探测失败。
- 瞬态失败只重试一次，并限制完整探测阶段的最长耗时。
- 最终失败后继续普通 SSH 终端连接，不显示连接期弹窗或 Toast。
- 删除目录回退弹窗中的 Shell 选择、Hook 命令和复制逻辑；保留本地启动目录或远程主目录回退。
- 更新高级设置和启用确认中的相关说明。

## Non-Goals

- 不改变 OSC 7 解析、成功状态 Tag 或 Shell 成功缓存格式。
- 不改变连接认证、主机密钥确认或 SSH 路由流程。
- 不把无法写入 PTY 的底层通道错误伪装成可用连接。

## Requirements

- REQ-001：探测通道打开、执行或等待超时等瞬态失败必须使用新通道自动重试一次；明确不支持的 Shell 不得重复探测。
- REQ-002：完整 Shell 探测阶段最长不得超过 4 秒；两次仍失败时返回无集成结果，由现有会话流程继续普通终端连接。
- REQ-003：探测最终失败不得产生连接期弹窗或 Toast；已启用但未收到 OSC 7 时继续使用既有灰色状态 Tag。
- REQ-004：手动 OSC 7 集成入口、前端 Hook 命令生成和复制逻辑必须移除；缺少当前目录时仍可显式打开本地启动目录或远程主目录。
- REQ-005：缓存命中和探测成功后的 Hook 注入行为保持不变。

## Acceptance

- AC-001（REQ-001）：自动化测试证明瞬态失败后最多再调用一次探测、第二次成功可返回 Shell、明确不支持只调用一次。
- AC-002（REQ-001, REQ-002）：自动化测试证明连续瞬态失败只执行两次，并验证单次及总探测超时常量不超过约定预算。
- AC-003（REQ-002, REQ-003, REQ-005）：代码路径和现有 SSH 测试证明无探测结果仍创建普通 PTY/Shell，会话失败提示没有新增分支，缓存成功路径保持有效。
- AC-004（REQ-004）：前端测试证明目录回退弹窗不再提供 Shell 选择、命令或复制动作，且本地与远程回退动作仍可用。
- AC-005（REQ-003, REQ-004）：设置界面不再承诺手动集成，改为说明一次重试和静默普通连接降级。

## Behavior Delta

### ADDED

- REQ-001：瞬态 Shell 探测失败会在有界时间内自动重试一次。

### MODIFIED

- REQ-002：探测最终失败从单次静默降级调整为至多两次、有总时限的静默降级。
- REQ-003：失败保持非阻塞、无主动提示，灰色状态 Tag 继续表达未收到目录信息。

### REMOVED

- REQ-004：移除用户选择 Shell、复制并执行临时 OSC 7 Hook 的手动集成路径。

## Risks

- 高延迟服务器可能触发瞬态重试；总探测预算必须避免显著拖慢登录。
- 不能把明确不支持误判为瞬态，否则每次连接都会产生无意义的重复命令。

## Open Issues

- 无阻塞项。用户已批准静默降级并保留目录回退的推荐方案。

- AC-003：Rust 全量测试 189 项通过、3 项环境依赖测试忽略；clippy 与 rustfmt 通过。会话层在无探测结果时继续创建普通 PTY/Shell 的既有路径保持不变。

- 真实高延迟 SSH 服务的 4 秒整体预算未在自动化环境中注入网络延迟验证；常量、调用次数和超时边界已由单元测试保护。
