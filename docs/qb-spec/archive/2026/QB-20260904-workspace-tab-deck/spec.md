# 工作区标签自适应堆叠

用户已采纳轻度横向叠放方案并授权实现。目标是在空间不足时保留当前工作区及其他工作区入口，避免标签和新增按钮相互遮挡。

## Requirements
- REQ-001：空间充足保持现有平铺；不足才叠放。未选中卡片至少露出 40px，超出容量横向滚动，加号始终可见且不覆盖窗口边框。
- REQ-002：选中标签始终保持正常 128px 宽度；另一个悬停或键盘聚焦标签可以展开。展开不改变顺序，不触发工作区切换。超长名称省略并提供完整提示。
- REQ-003：悬停对象不因动画下的边界移动而反复切换；鼠标离开恢复，点击固定展开。右键、重命名、拖拽期间固定预览。动效可中断，无弹跳；减少动态效果下直接布局。
- REQ-004：保留左右/其他批量关闭的一次确认、重命名、快捷键、拖拽排序及会话状态；拖拽使用实际可见几何。折叠标签关闭按钮不可误触。
- REQ-005：三种主题保持选中/悬停区别；标签底色遮挡下层文字，通知图标持续可见，通知气泡跟随可见锚点。

## Scope / Constraints
仅前端导航布局。沿用主题 token、React/CSS 与现有依赖；不修改持久化 schema、终端内容、窗口失焦透明度。将标签编排从 WorkspaceShell 提取，Shell 不增长。

## Approach
采用水平卡片和稳定的展开预留空间，避免扇形旋转。堆叠为视觉压缩，极多标签时保留滚动。单纯负边距 + hover 无法协调拖拽/命中/指示框，改用统一布局模型。

## Acceptance
- AC-001 / REQ-001：单个、临界宽度、多个、极多标签及缩放/关闭恢复场景符合布局规则；新增入口可点击且边框完整。
- AC-002 / REQ-002, REQ-003：选中+悬停同时完整显示；静止鼠标不会导致反复切换；键盘聚焦展开；移出恢复；减少动效不滑动。
- AC-003 / REQ-004：排序/关闭/重命名/快捷键回归通过，右键和编辑期间不会自动收缩，折叠关闭按钮不参与点击或键盘导航。
- AC-004 / REQ-005：深色/浅色/赛博主题可读、状态明确，通知锚点在可见区域并随位置更新。

## 2026-09-04 选中指示框定位回归修复
批量关闭左侧后从堆叠切回平铺，CSS transform 尚在过渡，getBoundingClientRect 包含旧位移；一次性读取令指示框在动画结束后仍停留旧位置。浏览器复现误差 520px。
改用相对于标签栏的 offsetLeft/offsetWidth 定位平铺指示框，避免堆叠/拖拽的临时 transform 污染；监听标签/容器尺寸及布局更新，堆叠状态跳过隐藏指示框的定位。
验证：先建立 2 项失败回归，再通过共 25 项相关测试、ESLint、TypeScript、source-size；浏览器检查左侧/右侧/其他批量关闭、单个前置标签关闭、堆叠恢复平铺、切换及拖拽排序，所有选中框均与当前标签对齐。

## 2026-09-04 极窄窗口溢出导航

- 点击箭头滚动一屏并保留约一个折叠标签的上下文，不切换工作区；触控板原生横向滚动继续可用。正常滚动平滑，减少动态效果设置下立即定位。

## 2026-09-04 悬停导航占位与首尾空白回归修复
原因：导航判定包含当前 preview，第二张卡片展开跨越溢出阈值后，箭头挂载改变视口并触发选中项自动滚动；鼠标下的卡片位置因此变化。禁用箭头使用 visibility:hidden，又将两端的固定按钮槽显示为空白。
改为按选中项加一张预览项的容量统一判定导航，判定不依赖当前悬停目标；因此预览展开/收起不会挂载或卸载箭头。边界箭头保留可见的低亮度禁用状态，替代隐藏空槽。选中项定位随卡片的实际动画位置更新，避免提前滚到尚未到达的目标坐标；普通 hover 不触发重新定位。
验证：增加临界宽度下首项选中、次项 hover 的导航节点稳定性及无重复滚动断言；浏览器连续 20 次轻微指针移动仅出现同一组预览和视口状态，最后选中标签到视口右侧约 1px；完整 pnpm check 通过（119 个文件、901 项前端测试及 13 项脚本测试）。

## 2026-09-04 折叠标签标题越界修复
最右侧折叠卡片已缩至 48px，但内部选择按钮仍固定 128px，缺少后续卡片遮挡时名称会伸出背景并扩大滚动内容范围。选择按钮改为随卡片宽度伸缩，并在按钮内裁切内容、沿用名称省略规则；卡片本身仍保留外部阴影和拖拽标记。
验证：78 项相关组件与样式测试通过；浏览器验证末尾折叠卡片宽 48px、按钮宽 46px，内容落在边框内部；悬停后完整展开至 128px。截图确认最右侧不再出现脱离背景的标题文字。

## 2026-09-04 悬停展开项的边界可见性
自动定位之前只处理选中项，导致末尾 hover 展开到 128px 后增加的宽度仍处于视口外。复用实际动画位置的最小滚动逻辑：有预览项时优先使预览项可见，否则继续完成选中项定位；已完全可见的卡片不滚动。保持原来的静止指针和预览目标保护，左右边界采用同一规则。
验证：新增回归覆盖末尾展开滚入视口、同坐标事件不切换预览、返回首项；浏览器分别在正常动画和减少动态效果下验证 48px 折叠卡片展开到 128px，右侧剩余约 0.11px，20 次轻微鼠标移动后仍保持完整展开。
完整 `pnpm check` 通过（120 个测试文件、902 项前端测试、13 项脚本测试，以及 lint、类型检查、生产构建）。

## 2026-09-04 展开宽度连续性与尾部边界修复
折叠卡片原先用 CSS 在动画宽度上额外加 8px，进入 expanded 状态立即取消该增量，导致实际宽度先缩小再展开。改为将折叠重叠宽度纳入动画目标，CSS 始终直接使用实际动画宽度，保证状态切换前后连续。
堆叠视口统一预留 8px 尾部空间，布局预算、滚动占位与可见性定位一致扣除/补回；自动定位向外取整并使用 instant，避免分数像素边框裁切和逐帧滚动与原生平滑滚动叠加。
验证：浏览器采样末尾卡片宽度从 48px 单调增加至 128px，并在后续采样保持 128px；右边框距视口约 8.11px。回归测试确认初始折叠动画宽度含重叠增量，并覆盖带尾部间距的展开定位。
完整 `pnpm check` 通过：120 个测试文件、902 项前端测试、13 项脚本测试，lint、类型检查及生产构建均通过。导航溢出阈值同步使用扣除尾部空间后的预算，保留空间充足时不显示箭头的行为。
