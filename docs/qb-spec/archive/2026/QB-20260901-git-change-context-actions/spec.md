# Git 更改右键操作与暂存区多选

## Goal

让用户可以在 Git 工作区更改和暂存更改列表中先选择一个或多个文件，再通过右键菜单批量暂存或取消暂存。

## Scope

- 工作区更改右键菜单新增“添加到暂存区”。
- 暂存更改新增与工作区一致的单选、Ctrl/Meta 多选和 Shift 范围选择。
- 暂存更改右键菜单新增“取消暂存”。
- 右键已选项时操作完整选区，右键未选项时先切换为该项单选。
- 保留工作区右键菜单中的抛弃更改入口。

## Non-Goals

- 不改变 Git 后端、暂存语义或批量 API 契约。
- 不为暂存区增加抛弃更改操作。
- 不改变行尾的单文件暂存/取消暂存按钮。
- 不合并工作区和暂存区的选择集合。

## Requirements

- REQ-001：工作区更改右键菜单必须针对当前选择提供单文件或批量“添加到暂存区”。
- REQ-002：暂存更改必须支持普通点击、Ctrl/Meta 切换和 Shift 范围多选，并保持选中视觉与 ARIA 状态。
- REQ-003：暂存更改右键菜单必须针对当前选择提供单文件或批量“取消暂存”。
- REQ-004：右键未选中项必须将操作范围切换为该项；右键已选中项必须保留并作用于当前同区选项。
- REQ-005：现有预览二阶段点击、工作区抛弃更改、行尾单文件操作、键盘上下文菜单和本地/远程 Git 路由必须保持可用。

## Acceptance

- AC-001（REQ-001、REQ-004）：工作区多选后右键菜单显示准确数量，执行后只以一次批量调用传递所选路径。
- AC-002（REQ-002）：暂存区的普通、Ctrl/Meta 和 Shift 点击产生与工作区一致的可观察选择状态。
- AC-003（REQ-003、REQ-004）：暂存区多选后右键菜单显示准确数量，执行后只以一次批量调用传递所选路径。
- AC-004（REQ-005）：未选中项右键、Shift+F10、抛弃确认、二阶段预览和行尾按钮的相邻回归继续通过。
- AC-005（REQ-005）：远程仓库通过既有 repository client 发送对应批量 stage/unstage 请求。

## Behavior Delta

### ADDED

- REQ-001：工作区更改右键菜单增加暂存当前选区的操作。
- REQ-002：暂存更改增加独立的多选状态与范围选择。
- REQ-003：暂存更改增加取消暂存当前选区的右键操作。

### MODIFIED

- REQ-004：Git 更改右键菜单从仅服务工作区抛弃操作扩展为按列表范围执行上下文操作。
- REQ-005：既有选择、预览和菜单行为在新增批量操作后保持兼容。

## Quality Check

目标、非目标、操作范围和验收闭合；用户已明确批准新增菜单与多选行为。实现复用既有 Git 批量 API，不引入后端或架构边界变化。

## Verification Evidence

- AC-001、AC-003：`GitPane.operations.test.tsx` 验证工作区与暂存区菜单显示准确数量，并各自只发出一次含精确路径的批量 `stage` / `unstage` 调用。
- AC-002、AC-004：Testing Library 验证未选中项右键、普通点击、Ctrl 多选、Shift 范围选择、Shift+F10、ARIA 选择状态及既有抛弃确认、二阶段预览行为。
- AC-005：远程仓库测试验证 `unstage` 通过既有 remote repository client 发送；现有远程 `stage` 路由回归继续通过。
- 样式契约验证上下文菜单复用主题化浮层，并保持普通操作与危险操作的既有语义样式。
- `pnpm check`：78 个测试文件、687 个测试全部通过；ESLint、TypeScript 类型检查和生产构建通过。
- `git diff --check`：通过，仅有工作区既有 LF/CRLF 提示。
