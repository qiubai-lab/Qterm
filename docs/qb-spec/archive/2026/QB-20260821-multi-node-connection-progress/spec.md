# 多节点连接进度组件规格

## 背景

Terminal、Files 与 Network 已共享带节点和阶段信息的 SSH route 事件，但连接过程目前使用通用文本提示展示。多跃点场景下，用户难以快速判断路径总长度、当前节点和已完成节点，成功后也缺少明确且短暂的收束反馈。

## 目标

- 为 Terminal、Files、Network 的 SSH 连接提供同一套悬浮式路径进度组件。
- 用节点圆点表达“本机 → 跃点 → 目标服务器”的完整路径。
- 已完成节点显示绿色；当前与待连接节点显示黄色，当前节点具有克制的脉冲反馈。
- 圆点下方显示当前连接阶段和节点序号。
- 全部连接完成后所有节点变绿，显示“连接成功”，约 1.2 秒后自动消失。
- 连接失败时隐藏进度组件，继续使用现有包含节点名称、地址与阶段的失败提示。

## 非目标

- 不修改 Rust SSH route 建连顺序、认证、主机密钥或隧道实现。
- 不持久化连接进度。
- 不用该组件替代 host-key 确认弹窗或详细失败提示。
- 不为三个窗口分别维护不同的进度模型或视觉实现。

## 行为规则

1. route 的可视节点数为后端 `SessionNode.total + 1`，额外节点代表本机。
2. 收到首个 route 事件后展示组件。本机及已经越过的 route 节点为完成态；当前 route 节点为活动态；后续节点为等待态。
3. `openTunnel` 表示前一节点已完成，活动位置推进到下一 route 节点。
4. `connect`、`verifyHostKey`、`authenticate`、`openTunnel`、`startSession` 分别显示稳定的中文阶段描述，并包含一基序号。
5. 收到 `connected` 后保留组件成功态约 1.2 秒；新的连接进度到来时立即重新显示并重置计时。
6. 收到 `failed` 或关闭态后移除进度；失败详细信息仍由现有 notice 展示。
7. 本地 Terminal/File 不展示该组件；直接 SSH 连接显示“本机 + 目标”两个节点。
8. 动画尊重 `prefers-reduced-motion`，高对比模式下节点边界保持可辨识。

## 验收标准

- 一个跃点连接展示 3 个节点圆点，多个跃点按路径长度增加。
- route 阶段推进时，已完成圆点逐步变绿，活动圆点保持黄色并显示对应状态文本。
- Terminal、Files、Network 使用同一个组件和同一个进度映射模型。
- 成功时全部圆点变绿并显示“连接成功”，约 1.2 秒后不可见。
- 失败时不与进度组件重叠，并保留现有节点级错误信息。
- 组件具备可读的 `role=status` 文本和非颜色的节点状态标签。
- 相关单元/组件回归测试通过，前端完整质量门通过。
