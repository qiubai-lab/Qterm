# Git 前端模块化拆分

## 批准记录

用户于 2026-08-31 明确采纳拆分建议并要求落地。实现从本规格进入 `active` 状态。

## 背景

`src/git/` 当前约 6,565 行，其中 `git.css`、`GitPane.tsx` 与 `GitPane.test.tsx` 约占 78.6%。`GitPane` 同时承担仓库访问、快照生命周期、操作日志、提交检查、浮层定位与界面渲染；`git.css` 同时承载工作区、提交图、分支操作、合并、仓库选择和响应式规则。文件增长已提高局部修改、回归定位与样式级联维护成本。

## 目标

在不改变 Git 功能、Tauri IPC、可访问性、视觉效果和用户交互的前提下，按稳定职责边界拆分 Git 前端代码与样式，使后续功能修改能够落在更小、更清晰的模块内。

## 范围

- 将 Git 样式按工作区、提交图、目标配置、操作浮层、仓库选择器和响应式规则拆分，并保留 `git.css` 作为稳定入口。
- 将 `GitPane` 中的本地/远程仓库访问选择、快照与操作编排、提交检查、浮层控制和展示组件拆到特性内聚模块。
- 按模块责任调整或补充测试，保留已有关键行为回归覆盖。
- 更新项目 Directory Map，记录新的 Git 前端边界。

## 非目标

- 不改变 Rust 后端、领域层、应用层、Tauri command 或 DTO。
- 不改变 Git 操作语义、错误文案、操作日志规则、分支合并流程或本地/远程路由。
- 不进行视觉重设计，不改变 DOM 可访问名称、焦点恢复、弹窗层级或动画策略。
- 不引入全局状态库、CSS Modules、通用弹窗框架或新的运行时依赖。
- 不以本次重构承担产物体积优化；Vite 的既有 chunk 警告不在本变更范围内。

## 约束与假设

- 当前工作树中的 Git 合并弹窗改动属于用户工作，拆分必须完整保留。
- `src/git/GitPane.tsx` 的导出路径和 `LayoutView` 的调用方式保持稳定。
- `src/lib/tauri/git.ts` 继续作为前端 Git DTO 与 IPC 函数的权威定义。
- CSS 拆分必须保持原有导入顺序，以维持同等特异性下的级联行为。

## Requirements

### REQ-001：稳定组合入口

`GitPane` 必须保留为对外稳定入口，并将仓库访问、控制状态、浮层和展示职责拆到 `src/git/` 内的内聚模块；展示组件不得直接调用 Tauri IPC。

### REQ-002：行为编排边界

本地/远程仓库访问选择、快照刷新、过期响应防护、忙碌与错误状态、操作日志、同步和合并流程必须从大段 JSX 中分离，同时维持现有行为和数据契约。

### REQ-003：样式边界

`git.css` 必须成为按固定顺序导入特性样式的稳定清单；每个样式模块应只覆盖一个清晰表面，并保留主题、减少动效、强制颜色和响应式规则。

### REQ-004：关键行为保护

测试必须继续覆盖本地/远程路由、过期请求防护、操作日志上限、同步部分成功、合并确认/冲突/中止/焦点、提交文件缓存和提示层定位；测试组织应与新模块责任一致。

### REQ-005：公共契约与文档

工作区对 `GitPane` 的导入和 Git IPC 契约保持不变；结构变更后必须更新 Directory Map。

### REQ-006：文件规模

拆分后 `GitPane.tsx` 应控制在 700 行以内；新引入的生产 TypeScript/TSX 模块应控制在 500 行以内，样式模块应控制在 900 行以内。确需例外时必须在计划或验证记录中说明。

## Acceptance Criteria

### AC-001（REQ-001、REQ-006）

`GitPane.tsx` 仅保留页面级组合和必要控制接线，行数不超过 700；新生产 TypeScript/TSX 模块均不超过 500 行，拆分后的 GitPane 测试文件均不超过 500 行，且展示模块中不存在直接 Tauri IPC 调用。

### AC-002（REQ-002、REQ-004）

现有本地/远程路由、刷新过期保护、操作日志、同步、合并、提交缓存和提示层测试全部通过；重构不改变用户可观察结果。

### AC-003（REQ-003、REQ-006）

`git.css` 仅维护有序样式导入；所有 Git 样式模块均不超过 900 行，样式契约测试从模块化入口验证原有选择器、主题和媒体查询。

### AC-004（REQ-004）

聚焦测试覆盖新提取的纯逻辑或边界；完整 `pnpm check` 通过，测试总量不得因拆分而减少关键场景。

### AC-005（REQ-005）

`LayoutView` 对 `GitPane` 的导入路径未变化，`src/lib/tauri/git.ts` 与 Rust 后端无行为性修改，Directory Map 已记录新的模块归属。

### AC-006（REQ-001 至 REQ-005）

合并弹窗及二次确认的现有视觉、层级、焦点与可访问性契约保持通过；未引入新的运行时依赖。

## Behavior Delta

不适用。本变更是行为保持型结构重构，产品能力、交互结果和外部契约均不应发生变化。

## 风险与缓解

- CSS 导入次序可能改变级联结果：按原文件顺序机械拆分，并用样式契约测试与视觉相关选择器断言保护。
- Hook 拆分可能产生陈旧闭包或竞态：保留 epoch 防护和现有 stale-request 回归测试。
- 浮层拆分可能影响焦点与层级：保留现有 ref、portal、`inert`、`aria-hidden` 和焦点测试。
- 本地/远程选择可能出现不对称：由单一仓库 client 边界集中路由，并复用现有 remote 测试。
- 工作树已有用户改动：仅在当前内容上做结构移动，不回退或覆盖既有变更。

## 验证摘要

- AC-001：`GitPane.tsx` 为 689 行；新增生产 TS/TSX 模块均小于 500 行，拆分后的 GitPane 测试文件为 85–252 行；presentation 模块未调用 Git IPC。
- AC-002：本地/远程路由、刷新竞态、操作日志、同步、合并、提交缓存和提示层的 38 个 GitPane 行为场景全部通过。
- AC-003：`git.css` 成为 9 个有序模块的 manifest；模块为 109–625 行，拼接后的 2,992 行声明流与拆分前逐行一致，样式契约测试通过。
- AC-004：`pnpm check` 通过，共 71 个测试文件、632 项测试，ESLint、TypeScript 与 Vite 生产构建成功。
- AC-005：`LayoutView` 继续从 `../git/GitPane` 导入；`src/lib/tauri/git.ts`、Rust 后端与依赖清单无修改；`docs/qb-spec/DIRECTORY_MAP.md` 已更新。
- AC-006：合并方向、二次确认、冲突/中止、焦点恢复和遮罩层级测试通过；未新增运行时依赖。
- 残余风险：未单独运行 Tauri 桌面视觉巡检；CSS 声明流等价、相关 DOM/焦点测试与生产构建提供了结构重构所需的自动化证据。Vite 仍报告既有的大 chunk 警告，本变更不处理产物分包。

## 规格质量检查

- 类型与层级：`design / standard`，与跨多个前端模块但无业务语义变化的重构相符。
- 可测性：每项要求均映射到可执行验收标准。
- 追踪性：使用稳定的 `REQ-*` 与 `AC-*` 标识，计划将维护要求到验证的映射。
- 范围完整性：明确包含样式、组件、状态边界、测试和目录文档，排除后端与视觉重设计。
- 未决问题：无。用户已批准按行为保持方案实施。
