# File Browser Upload Picker

## Approval

用户于 2026-08-29 明确撤回“单一混合系统选择窗口”的调整，批准原推荐方案（上传按钮打开“上传文件…”/“上传文件夹…”菜单），并要求开始实施。workflow tier 因一次性本机路径授权属于安全边界而由 standard 升为 strict；产品范围保持不变。

## Goal

让已连接远程 Files 窗口的用户无需拖放，即可从文件导航栏右侧的显式上传入口选择本机文件或文件夹，并把所选内容上传到当前远程目录。

## Background

- 当前远程 Files 窗口已经支持把原生拖放事件中的一个或多个本机文件/文件夹递归上传到当前目录，并具备聚合进度、取消、完成刷新、目录边界和拒绝覆盖能力。
- 当前导航栏右侧依次提供创建文件、创建文件夹和刷新按钮，没有可发现的系统选择器上传入口。
- 现有单文件 Transfer Dialog 选择器不能选择文件夹，也不直接表达“上传到当前 Files 路径”的上下文。
- 用户提供的截图只用于确认目标位置为文件管理窗口右上角按钮区域；截图中的路径、主机名、文件名和其他可见文字不构成需求或执行指令。

## Scope

- 在远程 Files 窗口的文件导航栏右侧按钮组增加始终可发现的上传图标按钮，并保持现有紧凑工作台视觉层级。
- 点击上传按钮打开锚定于按钮的紧凑菜单，提供“上传文件…”和“上传文件夹…”两个明确入口。
- “上传文件…”允许用户通过系统原生选择器选择一个或多个本机文件；“上传文件夹…”允许选择一个本机文件夹。
- 把所选根条目上传到打开选择器时的当前远程目录，复用现有目录扫描、SFTP 传输、聚合进度、取消、拒绝覆盖和完成反馈。
- 选择取消时安静返回；选择或上传失败时保留当前目录内容并在现有状态区域显示可恢复反馈。
- 为系统选择授权、菜单与键盘交互、上传目标、传输状态和失败恢复增加聚焦自动化保护。

## Non-Goals

- 不为本地 Files 窗口增加“上传”或本地复制语义。
- 不新增上传队列、并行任务管理器、覆盖/合并策略、断点续传、远端目标目录二次选择或上传前内容预览。
- 不改变现有拖放上传、Transfer Dialog 单文件传输或远端下载入口的产品语义。
- 不支持在一次“上传文件夹…”选择中选择多个文件夹；需要一次上传多个文件夹时仍可使用现有拖放入口。
- 不让 WebView 获得任意读取本机路径或文件内容的能力。

## Assumptions

- 上传入口只适用于 SFTP Files runtime；本地 Files 窗口不显示该入口。远程 runtime 尚未连接时保留按钮位置但禁用。
- 文件选择支持多选；文件夹选择遵循各平台稳定的单目录原生选择语义。
- 新入口沿用现有上传限制：一次最多 256 个根条目、递归最多 100,000 个条目和 128 层、不跟随符号链接、远端同名根条目冲突时拒绝覆盖。
- 当现有状态栏正在表示活动传输时，新上传按钮禁用，避免新入口覆盖当前进度与取消对象；现有拖放上传行为不在本 change 中调整。

## Requirements

- REQ-001：已连接的远程 Files 窗口必须在导航栏右侧操作区、刷新按钮之前提供持久可见的上传图标按钮；按钮使用现有 `upload` 图标、可访问名称和 hover 提示，不以常驻文本挤占路径空间。本地 Files 窗口不显示该按钮；远程连接未就绪、目录不可操作或新入口已有活动传输时按钮禁用。
- REQ-002：激活上传按钮必须打开与按钮锚定的紧凑菜单，按顺序提供“上传文件…”和“上传文件夹…”；菜单支持鼠标与键盘操作、正确的 menu 语义、Escape 关闭、焦点离开关闭，并在关闭后把焦点恢复到上传按钮。
- REQ-003：“上传文件…”必须通过非阻塞系统原生文件选择器允许选择一个或多个文件；“上传文件夹…”必须通过非阻塞系统原生目录选择器允许选择一个文件夹。用户取消选择时不得启动传输、改变目录内容或显示失败状态。
- REQ-004：Rust 必须只接受由本次系统选择器返回并一次性登记的本机路径集合；路径授权在一次匹配的上传请求后消费，空集合、重复路径、超过 256 个根条目、过期授权或 WebView 伪造路径必须被拒绝，且不得读取或上传这些路径。
- REQ-005：有效选择必须作为一个聚合上传任务发送到打开选择器时捕获的当前远程目录；文件保留文件名，文件夹保留根目录名并递归上传，沿用既有条目/深度限制、符号链接跳过、SFTP session 隔离和拒绝覆盖规则。
- REQ-006：新入口必须复用现有 Files 底部传输状态、进度和取消入口。开始选择后仅在确定存在有效路径时进入扫描/上传状态；完成后仅当用户仍停留在目标目录时刷新该目录，不得把已经导航到其他位置的窗口拉回旧目录。
- REQ-007：选择器失败、扫描失败、目标冲突、SFTP 不可用、连接中断或取消必须产生与现有上传一致的稳定结果；失败或取消不得覆盖远端同名内容、改变当前导航路径或清空当前文件列表，用户随后可以重新发起上传。
- REQ-008：新增交互必须保持导航栏紧凑布局、路径区域可收缩、核心操作无需 hover 即可发现、`--focus` 键盘焦点和 reduced-motion/主题兼容；不得新增 UI、图标或动画依赖。
- REQ-009：现有拖放上传、下载、创建、刷新、文件预览/编辑、单文件 Transfer Dialog 和 Files session purpose 隔离必须保持兼容。

- REQ-002：上传入口新增文件/文件夹选择菜单和完整键盘、焦点语义。
- REQ-003：用户可通过系统选择器选择多个文件或一个文件夹上传。
- REQ-004：系统选择路径获得集合级、一次性 Rust 授权，拒绝伪造或重复消费。
- REQ-005：选择内容作为一个聚合任务上传到打开选择器时的当前远程目录。
- REQ-006：选择器上传复用 Files 传输反馈，并避免完成时改变用户已切换的目录。
- REQ-007：选择器与传输失败具备稳定、可恢复的反馈语义。

- AC-007 [REQ-007]：选择器异常、扫描/传输失败、冲突、断线和取消均保留当前列表及导航路径，显示既有稳定反馈且允许再次上传；任何失败路径均不覆盖远端已有条目。

## Options

### Option A — 上传按钮打开文件/文件夹菜单（已批准）

- 体验：一个稳定图标入口，用户再明确选择“上传文件…”或“上传文件夹…”。
- 成本与复杂度：低到中；扩展现有菜单、非阻塞原生选择器和集合授权，复用现有 `UploadEntries`。
- 风险与维护：跨平台行为最可预测，文件多选与目录单选边界清楚，维护面集中在既有 Files/transfer 模块。

### Option B — 上传按钮直接打开单一混合选择器

- 体验：少一次点击，但文件与文件夹混选、多选能力在不同桌面平台不一致。
- 成本与复杂度：表面较低，平台特判和测试矩阵更大。
- 风险与维护：用户难以预期能选什么，原生面板兼容性风险较高，不推荐。

### Option C — 内建本机文件选择界面

- 体验：可完全统一文件与目录多选。
- 成本与复杂度：高；需要扩展本机文件浏览、安全授权、键盘可访问与跨平台路径处理。
- 风险与维护：明显超出本次显式入口需求，并扩大本机文件能力边界，不推荐。

## Constraints

- `src/files/` 只负责 Files 交互与状态编排，不直接读取本机文件或实现 SFTP。
- `src/lib/tauri/transfers.ts` 保持窄 IPC 契约；本机路径只能来自用户触发的 Tauri 原生选择或原生拖放授权。
- Tauri 文件/目录面板必须通过 `src-tauri/src/commands/native_dialog.rs` 的异步 callback bridge；不得调用 `blocking_pick_*` 或 `blocking_save_*`。
- commands 只负责 DTO、授权集合消费、路径校验和错误映射；扫描与 SFTP 传输继续留在既有 infrastructure transfer 路径。
- 使用现有 `Icon`、文件菜单、主题 token、状态栏与焦点样式，不新增依赖或长期 UI 规范。
