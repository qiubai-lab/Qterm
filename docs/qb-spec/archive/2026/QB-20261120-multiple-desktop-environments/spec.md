# 桌面多运行环境

桌面窗口聚合本机和多台 Qterm Server 的工作区。每个标签绑定一个运行环境，标签内现有的 SSH 目标功能继续可用。

| 需求 | 验收 |
| --- | --- |
| REQ-001 并行连接和隔离 | AC-001 本机、A、B 可以同时运行。终端、文件、凭证、锁定、延迟回调和下载按所属环境处理，即使工作区 ID 相同。 |
| REQ-002 新建与导航 | AC-002 无远程时直接新建；有已连接服务器时按钮和快捷键使用同一个环境选择器，默认聚焦当前可用环境，每个环境单独限制十个标签。重复连接定位到已有环境。 |
| REQ-003 主动断开 | AC-003 先保存该服务器工作区与草稿，提示受影响传输，再注销并从标签栏移除；保存失败保留现场。后台断开保留焦点，前台断开回到最近可用环境。 |
| REQ-004 恢复和异常 | AC-004 重连读取服务器布局并按既有规则接回仍存活的会话。网络中断、认证过期与接管保留标签和状态，其他环境可用。显式关闭的工作区不恢复。 |

## 实施与兼容性

原有整窗切换、注销和重载改为多个独立运行中的工作台。顶层只协调环境、标签摘要、导航和显式退出。每台服务器通过一个只加载应用自带页面的同源 frame 复用既有服务适配、独占登录和服务端权威数据。原生层按每次连接的独立标识管理固定上游、Cookie、下载和取消。远端 HTML 不在主窗口加载。现有布局与服务端存储格式继续使用。

验证覆盖身份冲突、重试、保存失败、迟到事件、后台退出和单环境上限，以及桌面端同时连接两台服务的实际操作。

## Behavior Delta

### MODIFIED

- REQ-001、REQ-002 将整窗切换运行环境改为同窗并行，并按标签归属路由新建、选择、关闭和保存。
- REQ-003、REQ-004 将全窗口注销改为单环境断开，沿用服务端原有会话保留、独占访问和草稿恢复机制。

## 验证

- AC-001、AC-002 在 Windows 的隔离开发配置中连接两个独立的真实 Qterm Server 和三个运行中的 Shell。按新建快捷键时焦点落在当前服务器，选择另一环境只在该环境新增标签。暂停 A 的文件写入请求，切到 B 后再放行，请求地址仍属于 A，A 的测试文件更新，B 的测试文件保持原值。
- AC-003、AC-004 在 B 前台断开 A，B 的选择和原终端会话均保留。重新登录 A 恢复原标签、原来的两个 PTY 会话 ID、后台输出和已同步的未保存文件草稿。已关闭的临时工作区从列表移除。停止 A 服务后，它的标签显示「重连中」，此时 B 仍能执行命令。测试截图在 `docs/qb-spec/evidence/QB-20261120-multiple-desktop-environments/offline-environment-picker.png`。
- 自动化覆盖工作区 ID 重名、原生代理和下载归属、草稿保存失败及重试、过期回调、断开期间其他环境可用、单环境数量上限、锁定和接管状态。Rust fmt、Clippy、桌面 Rust 测试、前端类型检查、构建、ESLint、源码体积检查和 Web 运行时测试通过。
- Windows 上完整 `pnpm check` 在 Node 安装脚本阶段有九项失败。同一主机用未修改的 HEAD 版本复现全部九项，涉及 macOS 路径分隔符、创建符号链接的权限和 POSIX 安装脚本环境。桌面 Vitest 测试通过。
