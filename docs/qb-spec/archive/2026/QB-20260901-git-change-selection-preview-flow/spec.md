# Git 更改选择与短文件预览优化

## Goal

让 Git 更改列表先明确选中目标，再由第二次点击打开预览；同时让短文件的预览表面连续铺满可用区域，减少审阅时的视觉割裂。

## Scope

- 预览型更改项首次普通点击只选中，不打开预览。
- 对同一个已选项再次普通点击时打开预览。
- 首次选中后显示短时气泡，提示“再次点击打开预览”。
- Ctrl/Meta/Shift 点击继续只处理多选或范围选择，不打开预览。
- Git MergeView 的左右编辑器背景铺满整个可用高度，空白区域不伪造行号。

## Non-Goals

- 不改变暂存、取消暂存、抛弃更改及右键菜单行为。
- 不改变 Git diff 数据、对齐算法、同步纵向滚动、独立横向滚动和 overview ruler。
- 不为真实文档以外的空白区域生成虚假行或行号。

## Requirements

- REQ-001：预览型更改项首次普通点击必须进入选中态但不打开预览，对同一已选项再次普通点击才打开预览。
- REQ-002：首次选中后必须显示短时、非阻塞且主题一致的“再次点击打开预览”气泡，并提供可访问的状态反馈。
- REQ-003：Ctrl/Meta/Shift 多选、范围选择、右侧操作按钮和右键菜单必须保持既有语义，不因双击式预览流程而误触预览。
- REQ-004：短文件预览的左右编辑器表面必须铺满差异舞台全部可用高度，空白部分不得生成行号。
- REQ-005：长文件的共享纵向滚动、各侧独立横向滚动、差异标识与 overview ruler 必须保持不变。

## Acceptance

- AC-001（REQ-001）：未选中项第一次点击后具有选中样式且没有加载预览，第二次点击同一项后打开对应 Git 更改预览。
- AC-002（REQ-002）：首次选中时出现角色为 `status` 的短时提示；打开预览、切换目标或超时后提示消失。
- AC-003（REQ-003）：修饰键点击只改变选择，暂存/取消暂存按钮仍只执行原操作。
- AC-004（REQ-004）：短文件左右 pane 的空白区域与编辑器使用同一主题背景，DOM 仍只包含真实文档行号。
- AC-005（REQ-005）：现有 Git 比较视图、滚动和 overview ruler 回归测试继续通过。

## Behavior Delta

### ADDED

- REQ-002：Git 更改首次选中后增加“再次点击打开预览”的短时气泡反馈。

### MODIFIED

- REQ-001：更改项由单击立即预览调整为首次单击选择、再次单击预览。
- REQ-003：多选与操作按钮在新预览流程下继续保持独立。
- REQ-004：短文件的可用空白区域由外层弹窗底色调整为连续的编辑器预览底色，且不增加行号。
- REQ-005：新交互与背景填充不得改变既有比较和滚动能力。

## Quality Check

需求、非目标和验收闭合；交互规则已由用户明确批准，样式变更局限于 Git 列表反馈和 Git 只读比较表面，不触及后端或普通文件编辑器。

## Verification

- AC-001、AC-002、AC-003：`GitPane.operations.test.tsx` 验证首次选择不加载差异、再次点击打开预览、修饰键只选择及暂存操作独立。
- AC-004：样式契约验证 MergeView、编辑器集合和左右 pane 使用 `--editor-background`；实际浏览器中三层背景与底部采样点均为 `rgb(9, 13, 18)`，左右 pane 高度完整覆盖 530px，行号止于真实文档末行。
- AC-005：Git 聚焦回归 42 项通过；`pnpm check` 通过（78 个测试文件、684 项测试，ESLint、TypeScript 与 Vite build 均通过）。
- 差异完整性：`git diff --check` 通过，仅有工作区 LF/CRLF 转换提示。

## Residual Risk

浏览器验证使用本地实际组件 fixture，而非 Tauri 原生窗口；交互、CodeMirror DOM、计算样式和完整前端构建均已覆盖，未发现剩余功能风险。
