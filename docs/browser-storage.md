# Browser environments

Browser tabs are page instances, not storage owners. `WebTabs` retains each page while selecting one visible guest. `WebHost` owns local and remote connection environments. Local uses the computer's network and system proxy settings without an SSH session; remote uses a validated SSH session supplying the immutable connection ID and route host/port/account snapshot. Same-identity pages across blocks share an environment. Identity changes select another environment; they never reuse another target's site data. Local is explicit: a missing or disconnected remote profile never falls back to it.

Each remote environment has a stable loopback gateway for this app lifetime. Guests on the same SSH session reuse one SOCKS listener; it is retired only after that session's final page closes. Removing one guest removes its gateway registration, and remaining guests continue through authenticated routes. The gateway never opens a remote socket directly. Closing/disconnecting an SSH session can interrupt in-flight requests or WebSockets carried by that session, even in another block sharing the environment; subsequent requests use surviving routes, but TCP streams cannot migrate. Local has no SSH gateway or watchdog. The existing global native-page limit remains 16; empty tabs do not allocate a native guest.

`cache/web-profiles/<opaque UUID>/profile.json` maps identity to browser-owned `data/`. The directory name never uses untrusted host/profile strings. Native browser storage persists after pages close. Metadata creation is staged before directory publication; old temporary browsing sessions are not migrated. Cookies/site data are not exported through IPC or configuration synchronization. This is native WebView2 protection, not whole-directory encryption. Cache directories may contain login-bearing site data.

The address-field popover offers resource cache, cookies and DOM storage. Resource cache is selected initially. Clearing serializes with guest lifecycle, pauses every current document in the selected environment, waits for blank documents, invokes the native profile API and restores their URLs even on failure. It reloads pages and can discard unsaved form data. Websites can create new cache/cookies after reload. App history, bookmarks and other connection environments are not cleared. No recursive profile deletion is used.

Local site data lives in the separate trusted `cache/web-profiles/local/data/` namespace with its own version/protection manifest. Existing remote UUID directories and manifests are unchanged. Local history/bookmarks use the reserved `local` scope in `device/web-library.json`; remote profile UUID keys remain unchanged. Neither local nor remote guests gain application IPC access.

Terminal link confirmations capture the source workspace/block/target when activated. Internal opening reuses a same-target browser in that workspace, using an empty tab or a fresh tab; if none exists, it splits beside the source terminal. A closed source, deleted connection or full tab strip reports an error. Local `localhost` refers to the computer; remote `localhost` follows SSH. External opening uses the system default browser and its own networking. Pending URLs are transient and never added to workspace persistence.

## Future master-password protection boundary

The persisted `BrowserProtection` mode is `native` today. `masterPassword` is reserved and rejected before opening the data directory; no switch is exposed until implemented. A future adapter must replace the storage resolver rather than teaching tabs or IPC how to read credentials.

Required transitions: available → quiescing → locked; locked → unlocking → available; available/locked → migrating → available/locked, with a recoverable failed state. All labels sharing the identity participate, including hidden tabs and other blocks. Close native views and wait for browser file release before sealing or moving files. Do not declare success while cleartext runtime data remains unintentionally accessible.

Enabling/disabling protection requires a transactional migration manifest and rollback to the last committed format. Never silently downgrade a protected profile to native mode, and never store keys or passwords in the manifest, URLs, logs or frontend state. Cookie-only encryption cannot claim to protect tokens in LocalStorage/IndexedDB. Unlock, OS-account/process threats, crash recovery and residual runtime files require a separate security design and native tests before this option is enabled.

Tab lists are not restored across app restarts; persistent site data and tab restoration are separate features. Guest IPC restrictions remain.

User-initiated webpage new-window requests (`target="_blank"`, `window.open`, new-window forms) are adopted into a new tab in the source block. The native WebView2 request is deferred and handed to a child using the exact source environment/profile; URLs are not replayed as GET requests, so POST payloads and opener relationships survive. `about:blank` is allowed as the initial popup document; subsequent navigation keeps the existing URL policy. Native window-close requests close the matching tab.

The opener plugin remains installed for explicit trusted-UI actions, with automatic JavaScript link interception disabled. Its default handler would cancel guest `_blank` clicks before native handling and attempt an unauthorized system-browser command. Application links (terminal confirmation, Markdown preview, project/about link and release page) use explicit open calls; guest permissions stay restricted. The application and native smoke share `infrastructure/external_links.rs` so tests exercise the same plugin behavior.

Automatic popups and prohibited targets are blocked. Requests have opaque single-use IDs, a 15-second timeout, a four-request per-source / sixteen-request global pending limit, and are canceled when the source navigates or closes. The existing ten-tab per-block and sixteen-native-page limits still apply. Frontend refusal and native creation failure release the deferral; a remote popup inherits its existing SSH target and cannot fall back to local. No popup URLs or requests are persisted.
